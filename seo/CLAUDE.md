## What `seo/` is

The **Jan–Mar 2026 SEO implementation archive** for genactiv.pl. It is not a library or an app: it is a mix of

1. **one-shot Python scripts** that wrote directly to the live Shopify store (meta descriptions, typo fixes), and
2. **client deliverables** (`.docx`, `.html`, `.md`, `.pages`) generated by `python-docx` report builders.

Almost every script is a *record of a completed migration*, not a reusable tool. Hardcoded collection/product IDs, hardcoded copy, hardcoded output paths. Re-running one replays a January 2026 dataset over today's store.

**Live SEO work happens elsewhere.** The current agent framework is `../genactiv-seo/` (12 specialist agents, `/seo-audit`, changelog, BEFORE/AFTER protocol) — see `../genactiv-seo/CLAUDE.md`. Sprint artefacts go to `../sprint-2026-06/W1/A1/artefakty/`. Prefer Shopify MCP tools (`update-product-seo`, `bulk-update-seo`, `get-seo-audit`) over adding scripts here.

**Keyword research lives outside this directory too.** Since 2026-08-17 Senuto is wired up (`SENUTO_API_KEY` in root `../.env`, `senuto-mcp` in `.mcp.json`). The reproducible pipeline is `../sprint-2026-06/W1/A1/artefakty/fetch_senuto_positions.py` + `build_keyword_map.py`, output `../research/keyword-map-2026.csv`. Do not add another keyword script here — extend those. API gotchas (per-module `country_id`, GET vs POST, 30-day JWT) are in the root `../CLAUDE.md`.

## Running the scripts

All scripts use the **root venv** and load `../.env` (`SHOPIFY_DOMAIN`, `SHOPIFY_ACCESS_TOKEN`, `SHOPIFY_API_VERSION`). Deps already installed there: `requests`, `python-dotenv`, `beautifulsoup4`, `python-docx`.

```bash
cd /Users/user/projects/genactiv-klaviyo
source venv/bin/activate
python3 seo/full_site_spell_check.py        # read-only crawl → report
python3 seo/create_seo_audit_report_v2.py   # read-only → .docx
```

No script takes arguments, has a `--dry-run`, or asks for confirmation. `main()` starts writing on the first line.

### Write scripts — treat as destructive

| Script | What it does on run |
|--------|---------------------|
| `add_all_collection_metas.py` | `collectionUpdate` on 24 hardcoded collection IDs |
| `fix_collection_metas_from_word.py` | Same 24 collections, alternate copy sourced from a Word doc |
| `fix_genacitv_typo.py` | Rewrites `body_html` on ~11 FUREVER products (GENACITV → GENACTIV) |
| `fix_genacitv_metafields.py` | Same typo fix across those products' metafields |

Two separate scripts overwrite the *same* 24 collections with *different* copy — they were competing drafts. Read the `COLLECTIONS_META` dict before running either.

**SEOInput hazard:** these scripts send `seo: { description: ... }` only. Per Shopify's `SEOInput` semantics (see root `../CLAUDE.md`), an omitted field is **cleared to null**, not preserved — so running them today wipes every SEO title on those collections. Any revival must read current `seo { title description }` first and send both back.

### Read-only scripts

- `full_site_spell_check.py` — crawls a hardcoded list of ~90 product/collection/blog URLs on the public site, regex-matches Polish spelling/punctuation/grammar/style patterns, and writes to **absolute paths**: `seo/PELNY_RAPORT_BLEDOW_GENACTIV.md` + `seo/bledy_szczegoly.json`. Adding a page means editing the URL constants at the top. The `FALSE_POSITIVES` list exists to suppress hits inside scientific citations (`Mol. Neurosci.`, `Medycyna Wet.`, …) — the ~530 unresolved "punctuation errors" tracked in the root CLAUDE.md are mostly this category, so tune `FALSE_POSITIVES` before treating new hits as real.
- `create_seo_audit_report.py` / `_v2.py` / `create_seo_capabilities_report.py` / `update_seo_word_final.py` — `python-docx` builders. `_v2` is the shipped version ("diplomatic wording, agency collaboration friendly"); the v1 is superseded. All content is inline Python literals, all copy is Polish, header cells use brand blue `0066CC`.

## Liquid snippets

`breadcrumbs-with-schema-*.liquid` are staged versions of the same `snippets/breadcrumbs.liquid` deployed to the theme:

- `-test.liquid` — BreadcrumbList JSON-LD gated to a single product handle (`colostrum-genactiv-60-kapsulek`) for Rich Results verification
- `-full.liquid` — gate removed, all templates

That test-then-widen pattern is the expected way to ship schema changes. These files are **source-of-record copies only** — the live version lives in the Shopify theme (deploy via `../shopify_theme_api.py`, and back up first).

## Document conventions

- `.docx` / `.html` / `.pages` = client-facing deliverables in Polish. `.md` = the working source they were generated from.
- Suffix `_FINAL` / `_v2` marks the shipped revision; unsuffixed siblings are earlier drafts kept for history.
- `ROC_`-prefixed files are parallel copies of the same reports under a different label.
- `SEO_PODSUMOWANIE_WDROZENIA.md` is the completion summary; `SEO_IMPLEMENTATION_PLAN.md` is the pre-work verification (per-collection/product ID inventory).
- `Genactiv_SEO_Analiza_Rekomendacje.md` is the strategic plan referenced from the root CLAUDE.md.

Note: `SEO_IMPLEMENTATION_PLAN.md` §7 contains a plaintext `shpat_` Shopify token committed in git history — it is stale documentation, not a live config path. Do not copy it into new code; scripts read the token from `../.env`.

## Before adding anything here

New SEO work belongs in `../genactiv-seo/` (agent + MCP + changelog) or a sprint task directory. Only add to `seo/` when the artefact genuinely belongs to this historical implementation. If a script here must be re-run, add explicit ID re-verification against the current store and read-before-write for every SEO field.
